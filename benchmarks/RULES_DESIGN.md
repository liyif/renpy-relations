# 多规则、少事实的交互基准

本页是旧24条件负载协议。扩大实际读取量的新协议见[CONDITIONS_DESIGN.md](CONDITIONS_DESIGN.md)。

事实数 : 导出派生规则数设为 1:1／1:10；默认 128／512 条事实，对应 128～5120 个派生规则。规则数是谓词／条件数量，不是派生结果行数。每次行动修改一个状态，在一个 batch 内 remove/add，保持事实数不变。

32 个剧情领域，各有少量状态事实；每个领域有两层共享前置条件及多个剧情条件。剧情条件读取共享的全局开关，且通过 NOT EXISTS 检查尚未发生的阻断事件。只有 24 个条件构成当前屏幕，分布在 12 个领域。

两种完全相同的逻辑分布：

- partitioned：领域状态在不同事实关系中，允许按关系隔离依赖。
- shared_table：所有领域状态放在同一个关系，由 WHERE domain 过滤。关系级图无法区分行／常量，应诚实显示局部修改引起广泛失效。

每个规模 × 比例 × 数据布局 × 模式 × 后端版本独立进程运行三次，版本顺序轮换，串行执行。对照版本来自固定 Git 提交 8827c21；新版本从当前源码复制。默认 cached／materialized／live 全覆盖。使用同一规则 JSON 和生成事实，验证每阶段查询结果。

阶段：空后端加载；公开事实导入；首次屏幕读取；重复屏幕读取；模拟历史遍历所有规则，确认完整结果；局部状态变化和屏幕读取；全局开关变化和屏幕读取；无规则依赖的备注变化和屏幕读取。

记录墙钟／CPU、RSS／进程高水位、每个读取样本、cached 失效数与新增物化数；提交时间包含完整快照。冷／warm 屏幕均是 24 个条件的整组耗时，不混为单次 has 延迟。历史遍历用于有意建立已访问条件的缓存，单独记录，不作为每次行动的成本。

本轮生成受控的简单 SQL 规则集，直接使用真实后端；不把生成 SQL 冒充全量 Logica 编译。真正 Logica 编译输出直接依赖信息的能力由编译器集成检查覆盖。负依赖、菱形依赖、循环、1050 层长链、失败事务由后端检查覆盖。长链加载另测一次，用来暴露 SQL 拓扑分析的祖先闭包成本，而非声称闭包算法对所有图都高效。

依赖解析使用 SQLite authorizer，图排序／循环检查／祖先和后继查询由 SQLite 执行；Python 不实现 SQL 解析器或 DFS/BFS。失效精度为事实**关系**级，包含否定／空表依赖；不做元组级增量维护。旧格式继续支持，新的 Logica 产物附加直接依赖清单，运行时校验它与 SQL 的实际读取一致，防止旧元数据导致错误缓存。

原始结果每阶段落盘，失败不填零，不加入完整成功汇总。使用 SDK Python 时不包括完整 Ren’Py 界面和历史追踪开销。DuckDB 是否更适合此负载需要独立后端对照；这里不更换数据库。
